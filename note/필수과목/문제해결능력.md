## 사고력

### 창의적 사고

- 끊임없이 참신한 아이디어를 산출하는 힘 

- 일상생활의 작은 영역도 창의적 사고 

- 누구든지, 언제나 창의적 사고를 하고있음

- 무에서 유를 만드는 힘이 아님

#### 발상법 종류

| 구분 | 방법 | 특징 |
|------|------|------|
| 자유연상법 | 브레인스토밍 | 자유롭게 아이디어를 내고 비판 금지 |
| 강제연상법 | 체크리스트법 | 질문 목록으로 강제로 아이디어 유도 |
| 비교발상법 | NM법, 시네틱스 | 다른 것과 비교·유추하여 아이디어 도출 |

##### 자유연상법
- 생각나는 것을 자유롭게 연상하여 아이디어를 얻는 방법
- 대표: **브레인스토밍(Brain Storming)**
  - 4원칙: 비판 금지 / 자유 분방 / 질보다 양 / 결합·편승 환영
- 기타: 브레인라이팅(서면 브레인스토밍)

##### 강제연상법
- 각종 힌트에 강제로 연결 지어 아이디어를 얻는 방법
- 대표: **체크리스트법(Checklist)**
  - 오스본의 체크리스트: 전용, 응용, 변경, 확대, 축소, 대용, 재배열, 역전, 결합 등 9가지 질문
- 기타: 속성열거법, 입출력법

##### 비교발상법
- 주제와 유사한 것을 비교하여 아이디어를 얻는 방법
- 대표: **NM법** — 자연·사회에서 유추하여 발상
- **시네틱스(Synectics)** — 서로 관계없어 보이는 것을 연결해 새로운 아이디어 도출
  - 유추 방식: 직접 유추 / 의인 유추 / 상징 유추 / 환상 유추

### 논리적 사고

- 의미
    - 사고 전개에 있어서 전후관계가 일치하는지 살피고 아이디어를 평가하는 능력 
    - 자신이 만든 계획이나 주장을 주위 사람에게 이해시켜 실현하기 위해 필요한 능력

- 구성 요소
    - 생각하는 습관 
    - 상대 논리의 구조화 
    - 구체적인 생각
    - 타인에 대한 이해 
    - 설득 

- 개발 
    - 피라미드 구조 방법: 하위 사실/현상부터 사고함으로써 상위 주장을 만들어가는 방법
    - So what 방법: 눈앞에 있는 정보로부터 의미를 찾아내어 가치 있는 정보를 끌어내는 방법 

### 논리적 오류

- 복합 질문의 오류: 질문 안에 입증되지 않은 전제를 숨김
    - 신고를 확인하지 않은 건 실수야? 아니면 고의야? 
    - 당신은 음주운전을 한 것이 나쁘다고 생각하지 않나요? 

- 원천 봉쇄의 오류: 상대 주장이 제시되기 전에 미리 신뢰를 차단
    - 이 문제에 대한 비판은 근거가 없으니 아예 들을 가치도 없겠지? 

- 결합의 오류: 부분의 성질을 전체의 성질로 잘못 확대함
    - 이 건물에 사용된 벽돌 하나는 가벼우니까 건물 전체도 가볍겠지? 

- 논점 일탈의 오류: 논의해야 할 핵심 쟁점과 관계없는 내용으로 결론을 이끌어 냄
    - 교통사고를 줄이자는 말은 옳지만, 자동차는 현대인의 필수품이잔항? 

- 애매성의 오류: 단어나 문장의 의미가 불분명해 여러 해석이 가능함
    - 우주에서 사람은 먼지에 불과하다니, 우리가 먼지로 이루어졌다고 하는건가? 

### 비판적 사고

- 의미
    - 어떤 주제나 주장 등에 대해서 적극적으로 분석하고 종합하여 평가하는 능동적인 사고능력 
    - 어떤 논증, 추론, 증거, 가치를 표현한 사례를 타당한 것으로 수용할 것인가 아니면 불합리한 것으로 거절할 것인가에 대한 결정을 내릴 때 요구되는 사고 능력 

- 비판적 사고를 위한 태도 
    - 지적 호기심, 객관성, 개방성, 융통성, 지적 회의성, 지적 정직성, 체계성, 지속성, 결단성, 다른 관점에 대한 존중
    - 비판적인 사고를 개발하기 위해서는 어떤 현상에 대해서 문제의식을 가지고, 고정관념을 버려야함.

## 문제해결절차(5)

### 문제 인식 단계

* 의미
  * 문제해결 과정에서 What을 결정하는 단계
  * 해결해야 할 전체 문제를 파악하고 우선순위를 정해 선정 문제의 목표를 명확히 하는 단계

* 절차(3)
  * 환경 분석
    * Business System상 거시적 환경 분석
    * 문제 발생 시 가장 먼저 고려
    * 3C 분석
    * SWOT 분석

  * 주요 과제 도출
    * 환경 분석으로 현상을 파악한 뒤 분석 결과를 검토해 주요 과제 도출
    * 다양한 과제 후보안 도출 선행
    * 과제안 간 수준 동일 여부, 표현의 구체성, 주어진 기간 내 해결 가능 여부 확인

  * 과제 선정
    * 과제안의 효과와 실행 가능성을 평가해 우선순위 부여 후 최우선 안 선정
    * 과제의 목적, 목표, 자원 현황을 종합적으로 고려해 평가

* 3C 분석(3)
  * Customer; 고객: 고객 니즈, 시장 규모, 구매 행동 분석

  * Competitor; 경쟁자: 경쟁사 강점·약점, 시장 점유율, 전략 분석

  * Company; 자사: 자사 강점·약점, 보유 자원, 핵심 역량 분석

### 문제 도출 단계

* 의미
  * 선정된 문제를 분석해 해결할 것을 명확히 하는 단계
  * 현상의 문제를 분해해 인과관계와 구조를 파악하는 단계

* 절차(2)
  * 문제 구조 파악
    * 전체 문제를 작고 다룰 수 있는 이슈로 세분화
    * 문제 내용과 영향 등을 파악해 문제 구조 도출
    * Logic Tree; 주요 과제를 나무 모양으로 분해·정리해 원인을 파고들거나 해결책을 구체화하는 기술
    * Logic Tree 작성 유의사항: 전체 과제 명확화 → 가지 수준 일치 → 원인 중복·누락 없이 전체 포함

  * 핵심 문제 선정: 문제에 큰 영향력을 미칠 수 있는 이슈를 핵심 이슈로 설정

### 원인 분석 단계

* 의미: 파악된 핵심 문제를 분석해 근본 원인을 도출하는 단계

* 절차(3)
  * 이슈 분석
    * 핵심 이슈 설정: 현재 수행 업무에 가장 크게 영향을 미치는 문제로 설정
    * 가설 설정: 직관, 경험, 지식, 정보 등에 근거해 일시적 결론을 예측하는 가설 설정
    * 가설 조건: 관련 자료·인터뷰 등으로 검증 가능 → 간단명료한 표현 → 논리적·객관적 내용
    * Output 이미지 결정: 가설 검증 계획에 따라 분석 결과를 미리 이미지화

  * 데이터 분석
    * 데이터 수집 계획: 데이터 수집 범위 결정
    * 데이터 정리·가공: 정보를 항목별로 정리
    * 데이터 해석: What, Why, How 측면에서 의미 해석

  * 원인 파악
    * 이슈와 데이터 분석 결과를 바탕으로 최종 원인 확인
    * 인과관계 유형(3)
      * 단순한 인과관계: 원인과 결과를 분명히 구분할 수 있는 경우
      * 닭과 계란의 인과관계: 원인과 결과를 구분하기 어려운 경우
      * 복잡한 인과관계: 두 유형이 서로 얽힌 경우

### 해결안 개발 단계

* 의미: 문제에서 도출한 근본 원인을 효과적으로 해결할 최적 해결방안 수립

* 절차(2)
  * 해결안 도출
    * 열거된 근본 원인을 제거할 시각과 방법을 명확히 설정
    * 독창적·혁신적 방안 도출
    * 전체 관점에서 해결 방향과 방법이 같은 안을 그룹화
    * 최종 해결안 정리

  * 해결안 평가 및 최적안 선정
    * 문제, 원인, 방법을 고려해 해결안을 평가하고 가장 효과적인 안 선정
    * 중요도와 실현 가능성(개발 기간, 개발 능력, 적용 가능성)을 종합 평가해 채택 여부 결정

### 실행 및 평가 단계

* 의미
  * 해결안 개발로 만든 실행계획을 실제 상황에 적용
  * 해결안으로 장애가 되는 문제 원인 제거

* 절차(2)
  * 실행계획 수립
    * What, Why, When, Where, Who, How의 답을 바탕으로 계획 수립
    * 실행 수립 고려사항(3)
      * 자원(시간, 예산, 물적·인적 자원) 고려
      * 해결안별 난이도를 고려해 세부 실행 내용 구체화
      * 실행 목적과 과정별 진행 내용 정리

  * 실행 및 Follow-up
    * 가능한 사항부터 실행해 문제점을 해결하고 해결안 완성도를 높인 뒤 전면 전개
    * 실행 단계 문제점 해결(3)
      * Pilot Test로 문제점 발견
      * 해결안 보완 후 대상 범위를 넓혀 전면 실시
      * 실행상 문제점 해결을 위한 모니터링 체제 구축
    * 모니터링 체제 구축 유의사항(5)
      * 바람직한 상태 달성 여부 확인
      * 문제 재발 방지 여부 확인
      * 목표한 기간과 비용 준수 여부 확인
      * 다른 문제 발생 여부 확인
      * 해결책의 영향 확인

## 문제풀이유형

### 명제

문장을 읽고 명제로 변환. 

```
푸딩을 좋아하지 않는 사람은 쿠기를 좋아한다.
푸딩O → 쿠키X
``` 
대우를 활용 

```
푸딩O → 쿠키X
쿠키 → 푸딩X
```

하나의 문장에는 여러개의 명제가 나올수도 있음

```
갑과 을은 항상 함께 참여한다. 
갑 → 을 
을 → 갑 
갑X → 을X
을X → 갑X 

치타가 사는 곳에만 코끼리가 산다. 
치타 → 코끼리 
치타X → 코끼리X
```

문장의 해석 

```
P만 Q이다 

Q → P가 성립 
P → Q가 아니다. 
```

### True-False Table

| | | | | | |  
|-|-|-|-|-| - |
| | A | B | C| D | E |
| A| 
| B |
| C |
| D |
| E | 

그리고 각 진술을 읽어가며 한개 column씩 채우기 

| | | | | | |  
|-|-|-|-|-| - |
| | A | B | C| D | E |
| A| T | F | T | F | F | 
| B |
| C |
| D |
| E | 

결과값이 많은 경우가 있을 수도 있음. 
예를 들어서 결과가 1~3명으로 구성되는 경우.
이런 경우는 선지에 나오는 결과값 사용 

| | | | | | |  
|-|-|-|-|-| - |
| | A, B | A, C | A, C, E| B, C, D | D, E  |
| A| T | F | T | F | F | 
| B |
| C |
| D |
| E | 

### 자리 배치

| 1 | 2 | 3 | 4 | 5 | 
| - | - | - | - | - | 

이런 식으로 테이블을 만들고 계속 재사용. 
을은 2가 아니다. 이런 건 관리하기 어려우니 패스. 확정적인 자리부터 채워나가기 

| 1 | 2 | 3 | 4 | 5 | 
| - | - | - | - | - | 
| 갑 |  | | | | 

확정적인 것을 더 찾기 어려우면 케이스 분기 시작. 

| 1 | 2 | 3 | 4 | 5 | 
| - | - | - | - | - | 
| 갑 |  | | | | 
| 갑 |  | 을  | | | 
| 갑 |  | | 을 | | 
| 갑 | 병 | 을  | 정 | |
| 갑 |  | 을  | 병 | 정 |

마지막으로 지문과 일치하지 않는거 지워내기. 

### 지문
